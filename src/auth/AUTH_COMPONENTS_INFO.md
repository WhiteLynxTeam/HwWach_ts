# Модуль аутентификации (Auth Module)

## Обзор

Модуль аутентификации реализует систему аутентификации и авторизации пользователей в приложении. Включает JWT-аутентификацию, локальную аутентификацию по логину/паролю и ролевую авторизацию.

## Структура модуля

```
src/auth/
├── dto/
│   └── login.dto.ts
├── auth.controller.ts
├── auth.module.ts
├── auth.service.ts
├── jwt.strategy.ts
├── local.strategy.ts
├── local-auth.guard.ts
├── roles.decorator.ts
└── roles.guard.ts
```

## Стандартные компоненты

### 1. auth.service.ts
**Назначение:** Сервис аутентификации
- Содержит бизнес-логику аутентификации (вход, обновление токенов)
- Интегрирован с сервисом пользователей для проверки учетных данных
- Генерирует JWT-токены с информацией о пользователе

### 2. auth.controller.ts
**Назначение:** Контроллер аутентификации
- Обрабатывает HTTP-запросы, связанные с аутентификацией
- Предоставляет конечные точки для входа и обновления токенов
- Использует LocalAuthGuard для защиты маршрутов аутентификации

### 3. auth.module.ts
**Назначение:** Модуль аутентификации
- Объединяет все компоненты аутентификации
- Импортирует UsersModule для доступа к пользователям
- Регистрирует стратегии аутентификации
- Управляет зависимостями между компонентами

## Дополнительные компоненты

### 1. jwt.strategy.ts
**Назначение:** Стратегия аутентификации JWT (JSON Web Token)
- Расширяет `PassportStrategy(Strategy)` из библиотеки passport
- Извлекает токен из заголовка Authorization (`Bearer <token>`)
- Проверяет подлинность токена с использованием секретного ключа из конфигурации
- Метод `validate(payload: any)` извлекает из токена `userId`, `login` и `role`
- Используется для защиты маршрутов с JWT-аутентификацией

### 2. local.strategy.ts
**Назначение:** Локальная стратегия аутентификации с использованием логина и пароля
- Расширяет `PassportStrategy(Strategy)` из библиотеки passport
- Использует поле `login` вместо стандартного `username`
- Вызывает метод `usersService.validateUser(login, password)` для проверки учетных данных
- Выбрасывает `UnauthorizedException` при неверных учетных данных
- Используется в процессе входа пользователя

### 3. local-auth.guard.ts
**Назначение:** Охранник (guard) для локальной аутентификации
- Простое расширение `AuthGuard('local')` для удобства использования
- Используется в контроллере auth для защиты методов аутентификации
- Инициирует процесс аутентификации по локальной стратегии

### 4. roles.decorator.ts
**Назначение:** Декоратор для указания требуемых ролей пользователя
- Использует `SetMetadata('roles', roles)` для установки метаданных
- Позволяет помечать методы или контроллеры требуемыми ролями
- Пример использования: `@Roles(UserRole.ADMIN)`

### 5. roles.guard.ts
**Назначение:** Охранник для проверки ролей пользователя
- Реализует интерфейс `CanActivate` для проверки прав доступа
- Использует `Reflector` для получения требуемых ролей из метаданных
- Проверяет, соответствует ли роль пользователя одной из требуемых ролей
- Используется вместе с `roles.decorator` для ролевой авторизации

### 6. dto/login.dto.ts
**Назначение:** DTO для данных входа пользователя
- Определяет структуру и валидации для данных аутентификации
- Содержит поля `login` и `password` с ограничениями длины
- Используется для валидации входных данных при попытке входа
- Валидации обеспечиваются декораторами из `class-validator`

## Взаимодействие компонентов

### Процесс аутентификации:
```
Login Request → AuthController → LocalAuthGuard → LocalStrategy → UsersService.validateUser → AuthService.login → JWT Token Generation
```

### Защита маршрутов JWT:
```
JWT Protected Route → JwtStrategy → Token Validation → RolesGuard → Roles Decorator → Access Granted/Denied
```

### Пример использования в контроллерах:
```typescript
@Post('login')
@UseGuards(LocalAuthGuard)  // Аутентификация по логину/паролю
async login(@Request() req) {
  return this.authService.login(req.user);
}

@Get('admin')
@UseGuards(AuthGuard('jwt'), RolesGuard)  // JWT + Ролевая проверка
@Roles(UserRole.ADMIN)  // Требуется роль ADMIN
async adminOnlyEndpoint() {
  return 'Admin only content';
}
```

## Архитектурные особенности

1. **Разделение ответственности**: Разные стратегии для разных типов аутентификации
2. **Безопасность**: Проверки валидации, шифрование паролей, JWT-токены
3. **Гибкость**: Возможность ограничения доступа по ролям пользователей
4. **Интеграция**: Тесная интеграция с модулем пользователей (UsersModule)
