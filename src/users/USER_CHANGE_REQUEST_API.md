# API для запросов на изменение данных пользователя

## Обзор

Система позволяет пользователям запрашивать изменение своих данных, которые затем должны быть одобрены администратором. Это обеспечивает контроль над изменениями в пользовательских данных.

## Доступные эндпоинты

### POST /user-change-requests/request
Запросить изменение своих данных (доступно только авторизованным пользователям)

**Тело запроса:**
```json
{
  "changes": {
    "firstName": "Новое имя",
    "lastName": "Новая фамилия",
    "phone": "+375291234567",
    "position": "Новая должность"
  }
}
```

**Пример ответа:**
```json
{
  "id": "uuid-запроса",
  "requestedBy": {
    "id": "uuid-пользователя",
    "login": "user_login",
    ...
  },
  "changes": {
    "firstName": "Новое имя",
    "lastName": "Новая фамилия"
  },
  "status": "PENDING",
  "requestedAt": "2023-01-01T00:00:00.000Z",
  "updatedAt": "2023-01-01T00:00:00.000Z"
}
```

### GET /user-change-requests
Получить все запросы на изменение (только для администраторов)

### GET /user-change-requests/{id}
Получить конкретный запрос на изменение (только для администраторов)

### PATCH /user-change-requests/{id}/approve
Одобрить запрос на изменение (только для администраторов)

**Тело запроса (опционально):**
```json
{
  "comment": "Комментарий к одобрению"
}
```

### PATCH /user-change-requests/{id}/reject
Отклонить запрос на изменение (только для администраторов)

**Тело запроса (опционально):**
```json
{
  "reason": "Причина отклонения"
}
```

## Допустимые поля для изменения

Пользователь может запросить изменение следующих полей:
- firstName (имя)
- lastName (фамилия)
- middleName (отчество)
- phone (телефон)
- position (должность)

## Статусы запросов

- PENDING: запрос ожидает рассмотрения
- APPROVED: запрос одобрен администратором
- REJECTED: запрос отклонен администратором

## Структура сущности PendingChanges

Сущность `PendingChanges` используется для хранения запросов на изменение данных пользователя и содержит следующие поля:

- `id`: уникальный идентификатор запроса
- `requestedBy`: информация о пользователе, который сделал запрос
- `requestedByUserId`: ID пользователя, который сделал запрос
- `changes`: объект с изменениями в формате JSON
- `status`: статус запроса (PENDING, APPROVED, REJECTED)
- `approvedById`: ID пользователя, который одобрил запрос (если применимо)
- `approvedBy`: информация о пользователе, который одобрил запрос (если применимо)
- `approvalComment`: комментарий к одобрению запроса
- `rejectedReason`: причина отказа в запросе
- `requestedAt`: дата и время создания запроса
- `updatedAt`: дата и время последнего обновления запроса
