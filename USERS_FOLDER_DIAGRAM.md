## Взаимодействия между классами

### 1. UsersModule
- Импортирует `TypeOrmModule.forFeature([User])` для доступа к репозиторию
- Провайдит `UsersService` как провайдер
- Регистрирует `UsersController` как контроллер
- Экспортирует `UsersService` для использования другими модулями (например, AuthModule)

### 2. UsersController
- Зависит от `UsersService` (через внедрение зависимости)
- Использует DTO для валидации входящих данных
- Использует декораторы NestJS для маршрутизации и безопасности
- Возвращает объекты User (без пароля)

### 3. UsersService
- Использует `@InjectRepository(User)` для доступа к репозиторию TypeORM
- Выполняет все основные операции с пользователями (CRUD)
- Валидирует данные, хэширует пароли с помощью bcrypt
- Проверяет уникальность логина и телефона
- Выполняет мягкое удаление (деактивация)

### 4. User Entity
- Определяет структуру таблицы в базе данных с помощью декораторов TypeORM
- Включает валидации с помощью class-validator
- Определяет перечисление UserRole (ADMIN/USER)
- Содержит поля: id, login, password, phone, имя, роль, активность и временные метки

## Поток выполнения

### При создании пользователя:
```
POST /users → UsersController.create() → UsersService.create() → User Entity → DB
```

### При получении пользователя:
```
GET /users/:id → UsersController.findOne() → UsersService.findOne() → DB → User Entity
```

### При аутентификации:
```
Auth Service → UsersService.validateUser() → User Entity → Password Comparison
```

## Типы зависимостей

- `UsersController → UsersService`: через внедрение зависимости
- `UsersService → User Entity`: через репозиторий TypeORM
- `DTOs → Controllers`: для валидации входных данных
- `UsersModule → TypeOrmModule`: для доступа к базе данных
- `User Entity → TypeORM`: через декораторы схемы
